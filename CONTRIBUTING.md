# Contributing

Contributions should improve a learner's causal understanding or reproducibility.

Before opening a pull request:

1. Explain the learner problem and the intended measurable outcome
2. Keep claims tied to a source map or a reproducible measurement
3. Run the content validator and site build when changing docs
4. Declare hardware, versions, cost, and safety boundaries for experiments
5. Do not commit model weights, credentials, private data, or unlicensed material

Large architectural changes to the site or curriculum require a short design note first. Chapter changes should preserve stable slugs and update the dependency map when prerequisites change.
