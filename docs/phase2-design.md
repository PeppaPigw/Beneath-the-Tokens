# Beneath the Tokens 二期教材重构设计书

## 1. 目标

一期已经完成 26 个章节、实验、Docusaurus 构建和 GitHub Pages 发布。二期不再把“达到字数”当作完成标准，而是把每章变成可学习、可审阅、可复现的研究型教材。读者应能先用直观模型理解问题，再从公式看到约束，从论文看到思想如何演进，从源码确认实现，最后用实验验证数量级并知道结论何时失效。

核心目标：减少 AIGC 味，增加真实教师的解释、停顿、例子、反例、逐步推理和诚实的不确定性。每节先回答新人正在问的问题，再引入术语；每个公式先解释变量和“为什么需要它”，再给推导；每个论文先说明它解决了什么失败，再说明方法；每个源码片段先给读者阅读任务，再展示调用链。

## 2. 教材写作规范

### 2.1 新人的认知顺序

每个新概念遵循“问题—直觉—最小例子—正式定义—机制—边界—练习”的顺序。禁止开头连续罗列术语。第一次出现的术语用一句生活化或运行时例子解释；随后再给英文名、符号和实现名。一个小节只引入少量新名词，上一节的概念必须在下一节再次使用。

### 2.2 叙述声音

像耐心的老师在白板旁讲解，而不是像论文摘要或产品宣传。少用“赋能、体系化、全面覆盖、值得注意的是、在此基础上、从而实现”等空泛连接词。多写“先看一个只有两个请求的例子”“这里容易误解的一点是”“如果把这个假设拿掉，结论会怎样”。允许短句、提问、停顿和承认暂时不解释的细节。避免把每段都写成同样的三句模板。

### 2.3 每节的最小教学单元

1. 本节要解决的一个具体困惑。
2. 一个可手算或可画图的微型例子。
3. 正式机制或公式，变量逐一解释。
4. 与真实系统的对应关系。
5. 一个反例或失败现象。
6. 两道由浅入深的问题，并给出答案或提示。

复杂章节再加论文谱系、源码导读和实验；不要把所有内容挤进同一段。

### 2.4 论文如何教给新人

论文不是参考文献列表。每篇论文写五件事：当时系统哪里慢/错/贵；作者观察到的关键瓶颈；核心想法用不超过一个页面的直觉和公式说明；实验如何证明或不能证明结论；今天的实现保留了什么、改变了什么。区分“论文在其硬件和数据上测到的结果”和“我们可以迁移的机制”。同时讲重要的负结果、争议和后来被替代的设计。

### 2.5 源码如何教

不贴大段代码。先给版本、目录和读者任务，例如“找出一次请求何时从 waiting 移到 running”。再画调用链，展示 20–40 行最关键的代码，逐行解释输入、状态变化、异常路径和指标。每个源码结论注明 commit/tag；如果 main 已改变，保留旧版差异表。

### 2.6 数学与实验

公式先用数字算一遍，再用符号推广。实验必须写清基线、变量、控制变量、环境、命令、原始输出、统计方法、误差来源和不能推断的部分。性能报告至少有 p50/p95/p99、吞吐、TTFT、ITL/TPOT、显存/KV 使用率和重复次数；不能只报平均 tok/s。

## 3. 二期完成定义

每个专题章必须具备：问题边界；第一性原理；数学模型和失效条件；奠基论文到当前系统的谱系；固定版本源码入口、调用链和数据结构；可运行实验与解释；失败诊所；至少两个方案的边界比较；研究问题；术语表；理解检查和答案；练习；来源地图；复现清单。内容标签统一使用事实、定义、推导、论文结果、源码观察、实验测量、推断、设计判断、未验证假设。

每章目标 2–4 万中文字符，基础章可按教学完整性调整。字数只是最低门槛，不能以重复解释或空泛总结凑数。

C 分布式训练：12 collectives/NCCL/拓扑/RDMA；13 数据/张量/流水/序列并行；14 ZeRO/FSDP/检查点/内存账本；15 MoE/专家并行/路由；16 Megatron/DeepSpeed/PyTorch Distributed 比较；17 弹性训练/抢占/恢复。

## 5. 网站交互设计

Docusaurus 继续静态发布。主题增加轻量阅读层：左侧 sidebar 和右侧 table of contents 各自拥有折叠按钮；折叠状态写入 localStorage；桌面端正文扩宽，移动端左栏改为抽屉、右栏改为可展开目录；按钮有 aria-label、键盘焦点和 Escape 关闭。章节标题下显示前置章节、预计时间、论文数、源码入口、实验入口和最后复核日期。代码块横向滚动，公式和表格适配窄屏，关闭导航后仍可通过标题锚点和面包屑阅读。

## 6. 审计与迁移

CI 检查 id 唯一、前置依赖、sidebar 收录、中文字符下限、教学结构、论文/文档/源码 URL、代码围栏、实验脚本语法和 Docusaurus build；网络失败与 404 分开报告。每章生成证据清单。阶段一提交本设计书、目录、模板、审计规则和 UI 设计；阶段二实现折叠布局和审计器；阶段三先重写 23、26、28、29、30 作为深度样板；阶段四按依赖重写其余章节；阶段五完整复现、构建和发布。

## 7. 冻结判据

所有章节有唯一编号和依赖；教学结构、论文—源码—实验闭环和 UI 行为写清；审计器能在一期内容上运行；用户确认本设计书。确认后再提交实现计划，避免继续在旧目录上堆叠内容。
