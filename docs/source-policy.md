# Source and evidence policy

The textbook triangulates claims across four source classes:

1. Primary papers and technical reports
2. Official documentation and reference implementations
3. Mature open-source source code and tests
4. Reproducible measurements and incident reports

Every chapter maintains a source map with URL, title, authors or project, version/date, claim supported, and access date.

A source is not automatically authoritative because it is popular. We distinguish:

- **Fact**: directly supported by a source
- **Mechanism**: reconstructed from code, docs, and measurements
- **Measurement**: observed under a stated environment
- **Inference**: reasoned conclusion
- **Design judgment**: our recommendation under explicit constraints

The book never presents a unit test, a benchmark, or a design document as proof of an end-to-end production property.
